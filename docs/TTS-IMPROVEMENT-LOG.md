## 问题与修改

| 原问题 | 修改后的行为 | 主要文件 |
|---|---|---|
| 收紧探活后，将真实服务裸GET的500误判为未启动 | 任一HTTP响应表示端口存活；不重复启动，POST业务错误仍抛出，释放响应体 | `engines/tts-core.cjs` |
| 缺参考原文时仍向V3/v4发送空串 | 默认可用性检查包含非空原文；合成前报明确中文错误 | `engines/tts-core.cjs` |
| 子进程启动异常没有完整处理 | 将启动错误、退出、信号、超时转换为可捕获异常并清理进程 | `engines/tts-core.cjs` |
| 启动与停止缺少协调 | 并发启动共用任务；停止取消启动与排队；只结束本模块启动的服务 | `engines/tts-core.cjs` |
| 服务异常时可能重复拉起并遗失原进程 | 运行中进程探活失败时保留句柄并报错 | `engines/tts-core.cjs` |
| 文本进入长 URL，多请求同时访问共用模型 | POST JSON；单实例串行推理，最多排队8条 | `engines/tts-core.cjs` |
| 只检查返回内容非空，响应内存无上限 | 有界流读取、RIFF/WAVE 文件头校验、UUID 文件名和失败写盘清理 | `engines/tts-core.cjs` |
| ffmpeg 报错后残留计时器或返回旧切片 | 释放计时器、限制错误日志长度、检查退出码和空产物 | `engines/tts-core.cjs` |
| 自动回复文件长期累积 | 无论发送成功或失败，均清理本次合成产物 | `bridge/voice-out.tts.js` |
| 合成期间状态改变仍继续发送 | 合成后重查静默、启用开关和额度；异常退回文本 | `bridge/voice-out.tts.js` |
| 缺少可重复的本机性能与波形检查 | 标准语料、首次/后续/并发测量、WAV 指标、试听文件及报告 | `scripts/benchmark-tts.mjs` |

上表中的引擎路径相对于 `packages/voice-out/`。
发送内核仍使用原有语音库边界、审计与回读校验机制。
`bridge/` 是接线参考片段，需要按 [接线说明](INTEGRATION.md) 合并到实际桥接仓库。

## 配置与兼容性

- `queueTimeoutMs`：引擎、自动回复、测速统一默认90000；DS v4实测三请求3/3成功，总19.12秒。
- `startTimeoutMs`：服务探活与启动预算，默认300000；v5手动启动到HTTP响应33.5/43.8秒，适配器spawn路径仍需实测。
- `timeoutMs`：HTTP 推理及响应体读取预算，默认 120000。
- `maxChars`：自动回复默认80，超过时完整发文本；引擎/基准本身不受该门槛限制。
- `maxBytes`：引擎默认 20 MiB，自动回复使用 `voice.maxBytes`。
- `minAudioSeconds`：默认1；较长文本低于此时长抛错退回文本，0关闭该启发式。条件见运维说明。
- `warmup({text, ...})`：显式执行一次推理、校验并删除预热WAV；不传text仍只保证HTTP存活。
- `VOICE_TTS_AUTO_START=false`：由外部守护服务管理Python时，在Node桥接进程中设置，避免两种管理方式争抢端口。
- 整合包目录：`VOICE_TTS_GSV_DIR` → 引擎旁 `gsv-dir.txt` 首行 → `./GPT-SoVITS`。
- 可用 `VOICE_TTS_PYTHON`、`VOICE_TTS_FFMPEG` 指定可执行文件完整路径。

各阶段独立计时，总等待时间可能为三个预算之和。已有显式配置需要同步修改，代码默认值不会覆盖旧设置。
每次合成返回独立文件，调用方负责释放；自动回复会自动清理，测速会保留试听副本。
串行保护仅覆盖同一进程内同一模块实例，不是跨进程或跨客户端的模型锁。

本轮增加三项防护，均保留服务所有权边界：

- WAV按fmt/data样本帧计算时长并返回 `seconds`；拒绝空数据、截断及不一致格式。
  至少10个中日韩字符/数字，或至少10个单词时，默认拒绝不足1秒的产物；
  短回复、单个英文词不受此下限限制。异常发生在落盘之前，桥接按现有错误路径退回文本。
  这是可配置的粗略防护，不保证识别所有漏字、静音或音质问题。
- `warmup({text: '足够长的预热句', ...})` 复用同一串行队列、参考材料和超时，执行真实合成并清理产物；
  失败返回false并记录原因。先预热成功再接收语音流量，避免首轮惰性加载占用正常回复的排队预算。
- 外部守护模式只复用服务，端口不响应时抛错而不再spawn；提供NSSM/systemd示例。
  短音频失败不触发自动重启，进程恢复由明确的管理者处理，避免重启其它客户端共享的服务。
